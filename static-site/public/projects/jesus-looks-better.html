JesusLooksBetter.com architecture and workflows

Client: Internal venture of Considerate Systems LLC · October 2026

Medusa Commerce EngineNext.jsStripe Payment APISanity CMSPostgreSQLDockerRaspberry PiCloudflare

An ecommerce site and blog that presents the gospel through long-form essays and sells made-to-order clothing and accessories, built on a headless commerce stack and self-hosted.

JesusLooksBetter.com leads with Christ for the Modern American, a series of fourteen essays, and carries a small collection: two printed tees and a handmade "Ambassador in Chains" keychain. Behind it is a complete headless commerce stack that I built and run myself, and it doubles as a working reference for the systems I build for clients.

Architecture

  • Medusa 2 commerce engine (Node.js) with PostgreSQL and Redis: products, carts, orders, and the admin dashboard used for fulfillment.
  • Next.js storefront, rendered on the server, with product photo galleries, cart and a multi-step checkout.
  • Stripe for payments. The browser confirms the card directly with Stripe, so card data never touches the server and PCI scope stays small.
  • Sanity holds the essays, read through Sanity's CDN, so writing and publishing never needs a deploy.
  • Docker Compose runs the whole stack, with Caddy providing automatic HTTPS and Cloudflare in front for DNS and edge proxying.

Order workflows

Every order is written to Postgres before anything else happens. Notifications are side effects of Medusa events, run as workflows, so a failed email can never lose a paid order.

  • Printed shirts go to a local print shop as an email with exactly what to print and where to ship it. The handmade keychain goes to its maker instead.
  • Because the shirts and the keychain ship from different places, checkout asks for a delivery method per package, and only offers the options that match what is actually in the cart.
  • The customer gets an order confirmation, a Stripe receipt, and a tracking email when the order is marked shipped in the admin.
  • Google Analytics follows the journey from landing page to sale. Short addresses printed on QR codes, stickers and the shirts themselves are tagged, so each printed source shows up as its own channel.

Hosting

The site launched on AWS: EC2 for the commerce engine, Amplify for the storefront, S3 for media and SES for email. In November 2026 it moved on-premises to a Raspberry Pi 4 with SSD storage, running the same containers. The data migrated with a final database dump and an automated rewrite of every media URL, with only minutes of checkout downtime. Nightly database and media backups now land on the SSD, and the hosting bill went from a monthly AWS invoice to the cost of the electricity.
